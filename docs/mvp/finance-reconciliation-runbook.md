# 历史财务数据只读盘点操作说明

本工具只检查经过明确授权、内容稳定的备份副本。它不会查找线上数据位置、加载应用状态、修改余额、修复记录、证明外部付款已完成，也不代表批准迁移。工具开发期间未读取或审计任何真实财务快照。

## 操作步骤

1. 向负责人员取得明确授权，以及不可变或内容稳定的备份副本。确认真实数据来源、执行后续迁移，都需要单独批准。不要直接检查仍在变化的线上存储。
2. 仅允许获授权的财务复核人员访问备份和报告。报告中的集合名称和记录序号也属于敏感运营信息。
3. 在项目目录执行 `node --import tsx scripts/audit-finance-snapshot.ts --input /absolute/path/to/authorized-copy.json`，将示例路径替换为获授权副本的绝对路径。工具没有默认输入路径，也没有修复或输出文件选项。请仅通过已批准的安全流程保存标准输出。
4. 查找原记录前，核对报告中的 SHA256 和字节数，确认对应的是同一份副本。定位信息使用从 0 开始的数组下标；钱包记录则使用从 0 开始的 `Object.entries` 枚举序号，刻意不输出对象键或用户标识。副本内容或顺序变化后，旧报告不能继续用于定位。
5. 逐条结合原始记录及独立凭证复核。`APPROVED` 不等于 `PAID`；找到历史扣款，也不代表链上付款已经确认。请保留原记录，将业务处置交由负责人审批，不要使用本工具修改数据。

## 退出码和运行错误

- `0`：报告已生成，没有数据级 `ERROR`，但仍可能存在 `REVIEW`。这不代表对账通过，也不代表可以迁移。
- `2`：报告已生成，存在数据级 `ERROR`。缺失或格式异常的集合、记录不能被当作空数据或正常数据。
- `1`：参数、文件读取或 JSON 解析失败，未生成报告。标准错误只输出固定错误码：`AUDIT_USAGE_ERROR`、`AUDIT_READ_ERROR` 或 `AUDIT_JSON_ERROR`。

输入必须显式指定普通文件的绝对路径。路径最后一段是符号链接、目录或非普通文件时会被拒绝；父目录中的别名仍可正常解析。工具只读取已打开并检查过的同一个文件描述符，不调用应用状态加载、持久化模块或数据库。

## 重点提示码如何理解

以下为常见提示，并非完整列表。`ERROR` 表示数据结构或字段存在问题；`REVIEW` 表示需要人工核实，不能据此直接认定损失、欺诈或付款结果。

- `APPROVED_PAYMENT_CONFIRMATION_REQUIRED`：提现记录已标记 `APPROVED`，但仍需独立付款凭证确认；即使有匹配扣款，也会提示。
- `APPROVED_MISSING_DEBIT`：在可明确关联的历史记录中，没有找到该提现对应的同用户负数 `WITHDRAW`。需要复核，不等于证明外部付款缺失。
- `WITHDRAWAL_DEBIT_AMOUNT_MISMATCH`、`DUPLICATE_WITHDRAWAL_DEBITS`：关联扣款金额与提现金额不符，或存在多条关联扣款；需要核实，不能直接认定重复收费。
- `NON_APPROVED_WITHDRAWAL_DEBIT`、`CROSS_OWNER_REFERENCE_COLLISION`：未批准的提现已有对应扣款，或同一提现引用关联到其他用户的记录，需要核查关系及操作历史。
- `UNATTRIBUTED_WITHDRAWAL_OWNER`、`UNATTRIBUTED_WITHDRAWAL_REFERENCE`：`WITHDRAW` 缺少用户或引用字段，无法可靠归属。它们属于待复核项，不会被默认为正常记录。
- `INVALID_TRANSACTION_TYPE`、`INVALID_TRANSACTION_OWNER`、`INVALID_TRANSACTION_REFERENCE`：流水类型不受支持，或已提供的归属/引用字段不是非空字符串，属于数据错误。
- `DUPLICATE_ID`、`AMBIGUOUS_WITHDRAWAL_JOIN`：标识重复或关联不明确，不应信任该关联所推导的扣款结论。
- `FRACTIONAL_ORDER_AMOUNT`：历史订单 `totalPrice` 含小数，仅提示人工复核，不会重新定价。

## 解释边界与安全限制

所有提示都是复核线索，不是欺诈、损失、重复扣费或付款成功的证明。通用 `WITHDRAW` 引用可能来自管理员操作，不会被自动判定为无对应提现或重复扣费。

流水必须使用已识别的类型。若提供用户或引用字段，其值必须是非空字符串；`null`、对象、数字等异常值会产生 `ERROR`。对于一般历史流水，这两个字段可以缺省；但 `WITHDRAW` 缺少任一字段会明确产生无法归属的 `REVIEW`。工具不会因为归属缺失，就虚构某笔外部付款未完成的结论。合法的通用管理员引用字符串仍保留其不确定含义。

历史流水混合了金币和钻石，工具不会将它们加总后声称等于钱包余额。工具不验证链上回执、币种归属、汇率、手续费、缺失历史、期初余额或经济处理是否正确。即使提示列表为空，也只是有限范围盘点，不是完整财务审计。

工具不会退款、重新定价、变更状态或修复记录。任何整改方案均须单独审批。
