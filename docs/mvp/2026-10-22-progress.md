## 工作流程和完成定义

状态：待梳理 → 待用户确认 → 可开发 → 开发中 → 测试中 → 独立复审 → 待产品验收 → 完成。其他状态：外部依赖、后置。

每项遵循：核对需求与现状 → 列明核心逻辑和边界 → 用户确认业务决策 → 技术方案 → 开发与针对性测试 → 缺陷自行修复 → 独立复审 → 更新证据和状态 → 按确认规则验收。

技术修复及客观功能验收由 QA/review agents 执行；只在新增/变更核心业务规则、边界或需要主观设计取舍时请用户确认，不逐项请求继续开发的许可。

纯技术问题（越权、并发重复执行、异常丢数据、构建失败等）由 agents 按现有意图修复。新收费、资金损失分摊、状态终态、用户处罚、争议裁定和功能删减不得自行决定。未确认的规则不得用默认值伪装为正式规则。

“完成”要求：需求有依据、边界明确、实现与测试一致、复审无未解决的严重问题、相应验收有证据。仅有页面、接口、代码或测试通过，均不能单独标记完成。
