# 社交注册与登录设计 v0.2

历史稿：当前视觉与动效以 [v0.3](social-v3-design.md) 为准；本稿保留字段、交互及参考来源记录，暖白／珊瑚配色已被用户要求替换。

日期：2026-10-08；状态：设计待确认。未进入业务研发，未提交或上传 GitHub。

预览：[本地设计](http://localhost:8766/social-v2.html)。源文件：`social-v2.html`；PRD：`../../product/PRD-auth-independent-pages.md` v1.1。本稿替代旧深紫 v0.1，不改首页／陪玩中心／后台。

## 1. 已明确的调整

用户要求顺序为邮箱 → 头像、昵称、性别、生日 → 标签；生日选择只允许已满 18 岁。用户随后回复“都允许”，确认头像可以上传照片或选择系统头像，必须选其一，不强制真人露脸。

设计目标是年轻、有社交吸引力、有真实相处氛围；不是把游戏陪伴产品改成约会平台，也不通过性感化人物或性别刻板印象制造吸引力。

这是设计取舍，不代表竞品已验证本平台的转化效果。UI/UX 技能用于控制文字层级、单一主动作、字段标识、点击区域、方向与对比度；没有直接套用其模板字体和配色。

比较方向：暖白＋珊瑚红更亲近自然，本稿采用；炭黑＋珊瑚红更夜间／电竞，作为备选但暂不混用；高饱和贴纸风更活泼，但容易造成新的杂乱，因此不采用。

## 3. 页面流程

1. **邮箱**：一个邮箱输入＋Continue with email。邮箱验证码校验沿用 v1.0，不能省略所有权验证。
2. **邮箱验证**：一个六位验证码输入，支持粘贴；修改邮箱、重发与失败恢复明确。
3. **个人资料**：头像选择／上传、昵称、性别、出生日期、必要协议。满足条件后创建正式账号，再进入标签。
4. **标签**：游戏偏好、相处风格、生活兴趣三类；推荐 3、最多 5、可跳过为待确认建议，不擅自改成强制 3 个。
5. **完成**：有原业务目标则恢复，否则首页；不自动下单、发消息、申请陪玩。

登录独立保留邮箱验证码和密码路径；密码作为次级文字切换而非两块高强调卡片。找回、设置新密码、账号受限沿用已确认业务要求。

## 4. 资料交互

### 头像

点击头像或 Choose/change avatar 打开一个选择面板：上方系统头像，下方 Upload a photo。两者同等可用，不默认勾选陌生真人照片。

本演示可以选择系统头像、读取用户自己选择的 JPG／PNG／WebP 并在当前页预览；示例最大 10MB。没有网络上传、读取相册全量或摄像头权限请求；刷新后清空。完整裁切、去除 EXIF、服务端审核与失败补偿属于后续实现，不把这里的预览当作已完成图片系统。

生产裁切确认稿：方形裁切区＋圆形安全区域，支持缩放移动；底部“重新选择／使用此头像”，不将裁切结果未经确认自动上传。审核失败保留昵称等资料，允许替换或改用系统头像。

### 昵称／性别

昵称 2–32 个用户可见字符，允许阿语、重名，不与登录邮箱绑定公开。性别本稿提案 Woman／Man／Rather not say，不预选；“不愿透露”表示已经完成此项选择，而不是自动猜测或强制公开。公开范围另设，待产品确认。

### 生日

字段必填且初始为空，日期选择器最大值为演示当日减 18 年。2026-10-08 时最大为 2008-10-08；差一天不允许继续。选择器限制与手动输入校验均有设计行为。

真实后端必须依据平台业务日期验证；本地演示使用设备日期，不能视为风控。不能用 18×365 天近似计算；闰日建议按非闰年 3 月 1 日到龄，最终时区与闰日口径研发前明确。

完整出生日期不公开，不进入公开接口／埋点。是否显示年龄是独立可见性选择，不因为收集了生日就默认展示。

### 标签

三组分别强调“玩什么、怎么相处、线下兴趣”。使用扁平胶囊标签，未选为细边框，选中为炭黑底和勾选；不让整页所有标签都使用强色。上限处显示明确提示，已选内容不丢失。

标签应使用稳定 ID 与本地化名称，不把“Chill duo”等自由文本变成身份或收费权限。标签保存失败不重复建号，不重建钱包。后续可在个人资料中修改。

## 5. 视觉规格

| 项目 | v0.2 |
| --- | --- |
| 页面 | 暖白 `#fffdf9`，评审外背景暖灰，不再使用紫色玻璃与光晕 |
| 文字 | 炭黑 `#26211f`；辅助 `#716a64` |
| 主按钮 | 珊瑚 `#ff806c`＋炭黑字，52px 高、14px 圆角 |
| 输入 | 50px 高、16px 字、12px 圆角、浅色细边框 |
| 标签／次级操作 | 44px 最小操作高度；选中不用发光效果 |
| 字体 | 同一系统 sans 家族；标题桌面 38、手机 33，正文 14–16，辅助 12 |
| 层级 | 标题 → 一句辅助 → 资料字段 → 单一主按钮；不在字段间插营销段落 |
| 桌面 | 46% 自然照片、54% 表单；表单内容最大 434px；不把表单铺满宽屏 |
| 手机 | 隐去大幅侧图，资料页优先操作；邮箱页可以展示一条 138px 氛围图 |
| 阿语 | 主体 RTL；邮箱、生日、验证码、英文品牌 LTR；不拉大阿语字距 |

顶部中文页面与尺寸工具只属于设计评审，不进入产品。重要信息不依赖颜色；表单有 label、错误文案、可见焦点，支持 reduced-motion；控件不禁用用户缩放。

## 6. 额外补充建议（非新增必填）

- 交流语言：比国籍更直接影响陪伴沟通，可在标签后或资料页选填。
- 国家／地区：按需用户自选，不请求精确定位，不用界面语言推断。
- 一句话介绍或破冰问题：例如“理想的一局是……”，主页后补，别让注册变成长问卷。
- 生日与性别公开开关、头像替换／审核提示：减少资料泄露和错误身份表达。
- 通知、联系人、摄像头权限在使用场景申请，不在注册阶段集中弹窗。

## 7. 验证与交接

检查记录见 `social-v2-validation.md`。设计演示不发邮件、不检查真实凭据、不创建账号、不改密码。示例填写按钮使用虚构资料且协议仍不自动勾选。

图片来源与完整生成提示见 `assets/social-editorial-v2.md`；它是虚构成年人物氛围示意，不是会员、用户证言或平台人数证据。

等待用户确认：视觉与排版、性别选项／公开范围、标签数量与跳过规则。头像双入口和 18+ 生日条件已经明确，不重复询问。确认后才形成实施计划，再走前后端研发与测试验收。
