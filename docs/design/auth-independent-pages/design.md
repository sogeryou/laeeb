# 独立注册与登录：设计评审稿（v0.1 历史稿）

本稿已被用户要求调整；最新权威设计见 [社交注册 v0.2](social-v2-design.md)，新预览为 `social-v2.html`，根入口自动跳转。以下保留为历史设计记录，不用于研发。

版本：v0.1；日期：2026-10-08；状态：待用户确认设计，未进入业务研发。

需求依据：`../../product/PRD-auth-independent-pages.md` v1.0（用户已确认）。

可视评审稿：同目录 `index.html`。它是隔离的设计演示，不接入 API、不发送邮件、不保存表单、不创建账号，也不改变现有 localhost:3001 产品。

## 1. 视觉方向

采用现有用户端 `AppShell.tsx` 的深紫背景 `#0f071a`、紫色主按钮、白色文字与半透明圆角容器；认证页不改动陪玩中心的绿色主题。使用项目现有文字品牌 LE3EB Club，不重新发明图形 Logo。

比较过的方向：

| 方向 | 评价 |
| --- | --- |
| A. 深色、低干扰认证页，桌面增加品牌侧栏 | 本稿采用；延续现有产品，手机上优先表单 |
| B. 大幅游戏人物插画背景 | 游戏氛围更强，但资源版权、加载与表单阅读成本更高；不采用 |
| C. 全白极简页面 | 表单清晰，但与当前产品风格跳变明显；不采用 |

UI/UX 技能检索结果仅作为参考：保留其紫色与表单可用性建议，未采用复古霓虹、CRT、虚构评价、等宽正文字体等与既有产品不一致的模板。

## 2. 评审方式

- 左侧或顶部中文菜单是设计评审工具，不是产品页面。
- 可切换手机／桌面、English／العربية、页面与异常状态。
- 默认展示手机登录。正常流程按钮可以切换演示页面；任何邮箱、验证码、密码输入都不离开本地页面。
- 验证码无真假校验，输入任意 6 位数字即可预览下一步。演示仅显示测试地址 `player@example.test`。
- 协议入口只打开“文案将在研发前使用正式版本”的设计说明，不构成签署；账号创建按钮只演示成功状态。
- 本稿不提供社交第三方登录按钮，不提供不可用的“快速赚钱”或注册奖励承诺。

### 登录

默认选中 Email code；Password 为并列次级切换。验证码模式的主按钮为 Send login code，密码模式为 Log in。两种模式都保留去注册和游客返回；密码模式增加 Forgot password?。不在切换时丢弃邮箱。

### 注册与验证码

注册使用“Verify email / Set up account”两段进度，邮箱输入和验证码同属第一段；减少用户感知的步骤数量，但不把验证与建号合并。

验证码采用一个真实输入控件，视觉上使用等距数字，不拆成六个独立的焦点。支持整段粘贴、系统一次性验证码填充、数字键盘；阿语页面中邮箱、验证码、倒计时仍为 LTR。

正常态提示有效 5 分钟，重发 60 秒；剩余时间由服务端驱动。前端不在计时末尾擅自假定验证码已验证或账号已创建。

### 完善账号

邮箱显示已验证且可返回修改；昵称 2–32 个用户可见字符。两项默认未勾选：

1. “I am 18 or older.”
2. “I accept the Terms of Service and acknowledge the Privacy Notice.”，协议与隐私分别可打开。

必须全部完成才能创建；不提供默认勾选，不把营销授权绑在必要确认里。不以昵称或头像证明真实身份。

### 兴趣引导

标题明确 Optional，右上角 Skip。优先游戏偏好与交流语言；地区、头像在下方可选区域说明和进入后续资料设置，不成为完成引导的门槛。最多选 5 个游戏并显示计数；没有选任何项目仍能 Continue。性别、身份证、收款账户不出现。

若存在原目标，在真实流程中优先回原目标，不强插引导；演示可以单独查看该页面。

## 4. 布局与规格

| 元素 | 规格 |
| --- | --- |
| 页面背景 | `#0f071a`；桌面侧栏允许很弱的紫色光晕，表单背后保持纯色 |
| 表面 | `#1a1128`；输入 `#21172f`；避免在文字下铺复杂背景 |
| 主色／主按钮 | `#7c3aed`，白字；pressed 更深，disabled 真正禁用 |
| 文字 | 主 `#f7f5fc`、次 `#b8aecb`、链接 `#c4b5fd` |
| 错误／成功 | 错误 `#fda4af`，成功 `#86efac`；必须带文字，不只改变颜色 |
| 字体 | 项目系统 sans-serif；阿语使用系统阿语字体回退，不为设计稿引入远程字体依赖 |
| 手机 | 375–430px 重点，320px 可用；左右 24px，390px 时表单宽 342px |
| 输入／主按钮 | 高度至少 52px；文字 16px；输入圆角 14px、主按钮 14px |
| 次级操作 | 至少 44px 高；可点击协议单独留足间距 |
| 间距 | 4/8px 标尺：字段 20–24px，标题到正文 12px，区块 32px |
| 桌面 ≥1024px | 独立全屏左品牌／右表单；表单内容宽 400px，左右留白至少 40px |
| 平板／窄窗口 | 隐藏品牌侧栏，表单居中；不是把手机稿等比拉大 |
| 短屏／横屏／软键盘 | 页面自然滚动，不把主按钮固定覆盖字段，保留安全区 |

设计稿默认只含与当前产品一致的深色主题；本期不新加浅色主题开关。

## 5. 状态设计与交互细则

| 状态 | 展示与操作 |
| --- | --- |
| 空输入 | 标签始终可见，placeholder 仅示例；提交时定位首个错误，不预先整页报红 |
| 格式错误 | 相关字段下说明可修正问题，不在未提交前不断打断输入 |
| 请求中 | 主按钮 Loading＋spinner，禁重复提交；保留返回帮助入口 |
| 邮件发送失败 | 页面内 alert，保留邮箱，可重试或修改；绝不进入“邮件已发送”状态 |
| 验证码错误 | 输入下提示“Incorrect or expired code. Try again or request a new one.”；保留重发／修改邮箱 |
| 限流 | 显示服务端可重试时间，不提供刷新页面绕过，保留联系客服 |
| 网络断开／超时 | 保留非敏感输入、显示重试；密码与验证码不持久存储 |
| 注册验证过期 | 提示重新验证，保留昵称等非敏感草稿；不显示已建号 |
| 已有账号 | 所有权验证后提示，主按钮进入原账号登录；不要求再次注册或覆盖旧密码 |
| 成功 | 图标＋标题＋结果，不以瞬时 toast 作为唯一提示；恢复页面前不自动执行下单／发送 |
| 重置密码成功 | 明示需要重新登录，唯一主按钮 Back to login |
| 年龄不满足／拒绝协议 | 不创建账号；旧账号保留客服和余额处理，不展示余额清零效果 |
| 旧资料待补充 | 区分“补充确认”与“新注册”，不清空原昵称、身份或数据 |
| 账号受限 | 具体文案来自后端允许披露的状态；设计稿展示通用说明，不渲染未经确认的处罚原因 |

错误提示优先字段内；网络／服务错误放表单上方，使用 `role=alert`。验证码倒计时不每秒读屏播报。路由变化后聚焦主标题；提交错误聚焦首个无效项；手动切换语言保留邮箱及步骤，不保留跨用途的验证权限。

原目标恢复真实行为由后端与受控路由共同确定；设计稿不接受任意外域 returnTo。顶部“Back to browsing”在真实产品回来源或首页；演示仅提示不会离开预览。

## 6. 阿语与无障碍

- Arabic 下页面布局与文字为 RTL，返回箭头镜像、顺序从右至左；英文品牌、邮箱、验证码、密码和数字保持 LTR 并使用方向隔离。
- 不把字体字距应用到阿语正文；允许阿语句子换行，不截断协议／错误信息。
- 每个输入都有 label；主次操作提供可见键盘焦点；颜色对比按普通文字至少 4.5:1 检查。
- 用户可缩放；默认输入 16px；动效只限 150–200ms 的 opacity／颜色变化，并尊重 reduced-motion。
- 密码有 show/hide，辅助技术可知当前状态；不限制粘贴，不显示具体弱密码泄露来源。
- 本稿阿语为初版界面文案，需在上线前由母语审校；不宣称已通过语言专业验收。

## 7. 前端交接边界

拟议组件：AuthPageLayout、AuthMethodSwitch、EmailField、VerificationCodeField、RegistrationProgress、ConsentFields、AuthFeedback、OptionalGamePicker。与原业务页面复用颜色和圆角，不拆改首页／陪玩中心。

状态建议分开保存：页面流程、邮箱所有权凭据、服务端限流时间、账号会话。不能用“当前处于资料页”代替服务端注册凭据，不能用 UI disabled 代替后端限流。

管理员入口保持原样；不把用户端 UI-01 直接套到后台产生管理员注册。旧用户迁移按 PRD 的 user_id、钱包、订单、等级、私信保留要求验收。
