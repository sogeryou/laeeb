# 动态与评论审核实施计划

**Goal:** 实现用户已确认的先审后发、通过日计分和违规下架复核规则。

**Architecture:** 新增独立内容路由，复用现有认证、REVIEW_MODERATE 管理权限、JSON 存储。内容状态 PENDING → APPROVED / REJECTED，APPROVED → REMOVED；本批不开放恢复或作者编辑，避免未确认的再次计分规则。

**Tech Stack:** Express、React、TypeScript、Vitest/Supertest。

## 约束

- 不更改登录注册；原动态布局不重做；只本地开发、不提交上传。
- 待审核、驳回及下架内容仅作者和有权限的审核员可见；公共列表仅 APPROVED。
- POST 事件使用首次审核通过时间，按平台时区自然日去重，5 分/日、15 分/周。
- 下架令事件失效，未结算周重算；已结算周生成复核记录，不改正式等级或原结算记录。
- 评论通过后公开，不产生动态任务积分。
- 驳回和下架原因必填；重复相同操作幂等；互相冲突状态返回 409；保存失败恢复内存。
- 历史无审核信息内容不视为已审核，不销毁原文；历史积分迁移需单独核对，不能自动改历史等级。
