# 招呼新用户任务：本地验收

## 规则与交互

- 陪玩中心 → Player Level → Task Center → Find New Users to Greet。
- 候选用户在发出招呼时，尚未在该陪玩处完成过任何订单；取消、待完成订单不算已完成订单。资格在发送时确定。
- 填写文字并发送，成功后进入原私信页；发送本身不加分，普通私信也不会自动成为任务招呼。
- 用户在招呼发出后 24 小时内回复（含恰好 24 小时），服务端记录有效奖励。同一用户对同一陪玩终身只奖励一次。
- 每次 5 分，按实际回复时间归入平台自然周，每周最多 50 分。超过上限仍保留有效互动记录，不在以后周重复奖励。
- 等待回复时不能重发招呼延长窗口。超时未获奖可重新发出招呼；继续沿用终身去重。
- 列表可查看等待回复和到期状态、刷新及加载更多；发送失败保留草稿与幂等请求标识。
- 候选接口不返回邮箱、电话、密码等私密字段；消息封禁、发送频率限制沿用私信规则。

## 接入与数据

- `GET /api/social/greetings/candidates`：已审核陪玩身份、公开字段、20 条分页。
- `POST /api/social/greetings`：服务端验证资格、生成招呼发送时间与到期时间，复用私信存储。
- `POST /api/social/messages`：回复时判断有效招呼，消息与等级事件一同保存；保存失败一同恢复。
- `GET /api/player-center`：返回 greet 接入标识与真实有效回复人数，前端按每周上限展示。
- 旧文字消息没有招呼标记，不自动补发历史积分；无需改变已有消息结构或迁移旧记录。

## 验证入口

- `tests/integration/greetings.spec.ts`：发送不计分、普通私信不计招呼、24 小时边界、跨周、终身去重、周上限、权限、候选分页、老客排除、幂等冲突和写入失败回滚。
- `tests/unit/player-center-original.spec.ts`：服务器任务数据适配、真实招呼人数、保留原入口。
- 隔离预览账号：陪玩 `player@local.test`，新用户 `new0@local.test`；测试密码均为 `PreviewOnly123!`。
- 新预览含 25 位从未下单的测试用户，原 26 位已完成订单的测试客户不会混入候选列表。

## 2026-10-08 实际验收结果

- 浏览器中从原陪玩中心进入任务页，点击招呼入口，列表展示 20 位新用户及加载更多入口。
- 陪玩提交招呼后进入原私信页，消息正常展示；此时有效招呼人数为 0。
- 隔离新用户通过真实接口回复两条消息，浏览器私信页刷新显示两条回复。
- 返回任务页，招呼积分为 5/50，本周活动预估从 3 分变为 8 分；已获奖用户不再出现在候选列表。
- 临时 JSON 数据保存 1 条带招呼标记的消息、1 条招呼奖励事件，第二条回复未重复领奖。
- 80 项自动化测试通过，前后端类型检查通过，生产构建通过。构建仍有既有的大包体积提醒。
- 代码审查发现并修复了登录令牌变化时旧发送请求可能使按钮一直禁用的问题；旧请求也不会解锁新账号的新发送请求。
