# 动态/评论先审后发：本地开发验收

## 已确认的产品规则

- 提交后待审核，仅作者与审核员可见；通过后公开，驳回显示原因。
- 动态积分按首次审核通过时间归入平台时区自然日、自然周；5 分/日、15 分/周。
- 评论不产生动态任务积分。
- 违规下架撤销对应动态资格，同日还有有效动态则保留当日分。
- 已结算周创建 PENDING 复核记录，系统按下架前后的有效动态任务分差计算建议抵扣额，避免同日重复扣分。
- 复核确认后进入 CONFIRMED；在确认时间所属周或之后的首次有效周结算抵扣，不回写原结算。结算后变为 APPLIED，记录实际抵扣和放弃分数。
- 积分最低为 0；当周不足扣的余量直接放弃，不结转、不追扣。扣分参与当次周结算的升降级判断。
- 后续第三方风控直接提供审核结果，沿用现有通过/驳回/下架处理链，不额外增加一轮内容人工审核。本次未接入实际供应商或开放无鉴权回调。

## 接入位置

- 用户端：Community → My posts & review status；动态详情可提交评论并查看自己的审核状态。
- 后台：Review Moderation → 动态与评论审核，可筛选动态、评论、已结算积分复核，执行通过、驳回、违规下架。
- 驳回、下架必须填写原因；审核历史保留操作者与时间。
- 鉴权与管理权限复用原系统，未修改登录注册。

## 验证结果

- 浏览器：提交动态后显示 PENDING；切换公共列表无该动态；管理后台通过操作后待审核队列移除该记录。
- 本地双账号接口验收：通过后动态积分 5；同日两条通过动态下架一条仍为 5，全部下架变为 0，公共列表为 0。
- 待审核评论作者看到 1 条，其他用户看到 0 条；驳回后作者可读取原因。
- 自动化测试覆盖跨周通过计分、重复通过不重复加分、权限、下架重算、已结算复核、保存失败恢复及任务快照失效。

## 未决事项与未覆盖范围

- 后台已支持确认抵扣、无需抵扣和处理说明，不能任意输入抵扣额。没有系统建议值的旧复核记录不自动确认，避免猜测历史积分。
- 自动周结算调度仍未启用；上述抵扣已接入现有内部周结算引擎，仍受数据完整性保护约束。
- 驳回后编辑重投、下架恢复、作者删除及其积分口径尚未确认，本批未开放。
- 旧版本无审核记录的动态不视为审核通过；历史旧 POST 事件未自动迁移或扣减，若接入真实旧数据须先核对迁移口径。本地验收使用新建隔离数据。
- 点赞、关注、拉黑、举报入口的完整业务，图片/语音、礼物、自动周结算仍不是本批完成项。文字招呼后续已接入，详见 `greeting-tasks-local.md`。
- 本地 JSON 存储沿用单进程实现，不声明多节点事务能力。
